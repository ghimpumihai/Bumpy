# Dashboard rules

The dashboard reads only the read API. Its contract is [API.md](API.md), with types in `src/types/` and a mock backend in `src/mock/` that implements the same routes; every response is checked by `expectShape` (`src/utils/api-shape.ts`). Contract changes follow the root `CLAUDE.md`.

## Structure
- `src/mock/` is reachable only through `configureApiClient` (dynamic import); depcruise enforces it.
- Network calls only in `src/api/<feature>/index.ts` (exports `<feature>Api` and `<FEATURE>_QUERY_KEY`); env only via `@/config/env`, never `import.meta.env`.
- Routes stay thin: Zod-validated search params (`views/<feature>/schema.ts`) are the filter state, so every view is a shareable link.
- `routeTree.gen.ts` is generated by `npm run dev`/`npm run build`; never edit it, do commit it.
- Types shared across files live in `src/types/<domain>/`; everything else stays next to its use.

## Data fetching
- Polling: the live view every 2 s (`LIVE_POLL_INTERVAL_MS`, no retries: polling is the retry); recording/processing trips every 5 s until finalized; aggregates every 60 s; finalized trips never poll.
- A trip's own data (series, track, events, labels) is keyed by "finalized", so it's fetched again when the finalize job replaces the live results.
- Use `QueryState` with `hasData`: a failed background refresh keeps the loaded content with a small notice. Map overlays use `ErrorAlert` instead, so the map stays visible.
- Forms: `useWatch`, not `watch` (React Compiler). `shouldUnregister: true` only for forms reused across entities; a hidden field (the API URL in mock mode) stays registered and the schema decides when it's validated.

## Domain rules (plan 02 §5, §8, §10; API.md)
- `source` = how a trip reached the cloud (Streamed / Uploaded / Replay); `status` = Recording → Processing → finalized; `incomplete` is a separate flag. Never call a finalized streamed trip "live".
- Only finalized trips count in the map; always show *why* a trip doesn't (`EXCLUSION_LABELS`).
- Live freshness uses the server clock and distinguishes "behind the phone", "no data" (dead zone), "catching up", "trip ended" and "read API unreachable". Never claim "live" for old data, never blame the phone for the dashboard's own outage.
- Everything on the map must also be reachable by keyboard (the worst-segments list).

## Maps and charts
- `MapCanvas` exposes the map after `style.load` (not `load`, so data doesn't wait for tiles) and falls back to a plain style when offline.
- Add data only with `GeoJsonLayer`, never `map.addLayer` in views. It creates its source and layers once per style and applies later changes in place (`setPaintProperty`/`setLayoutProperty`/`setFilter`). Segments and tracks go below the event dots (`beforeId`).
- Map and chart colours come from CSS tokens via `useThemeColors`, re-read when `<html>`'s class changes, never from theme state.
- Charts in one view share a uPlot `syncKey`.

## Conventions
- Colours only from the semantic tokens in `src/global.css` (incl. `scale-1…5`, `event-*`, `chart-1…5`), never raw palette classes. Inline `style` only for runtime geometry or runtime CSS-variable colours.
- Dates via `@/utils/format-date-time`, numbers and units via `@/utils/format-number`, physical constants in `constants/units.ts`; toasts only via `useToast()`.
- Constants sit next to where they're used; move one to `constants/` once it's shared.
- Closed sets are const objects + `typeof` types, not `enum`s. File and folder names kebab-case, except `routes/` and `components/ui/`.
- UI copy is English.

## Done means
- `npm run check` and `npm run build` pass. Run `npm run test:e2e` (slow: every route, console errors, axe in both themes) before merging to `main`, not on every change.
- Don't write new tests for views or UI; keep the existing mock-backend tests passing (they pin the plan's rules).
